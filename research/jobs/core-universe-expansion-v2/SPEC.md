# 코어 ETF 후보군 자산군 확장 v2 — v1 배관 버그 수정 재실행 (core-universe-expansion-v2)

등록 2026-10-10. 결과를 보기 전에 이 문서와 `run.py` 의 판정 코드를 고정한다.

## 왜 v2 인가 (v1 무효 사유)

core-universe-expansion-v1(2026-10-07 실행)은 IWM·TIP·VNQ·VWO·LQD 와 5종 묶음 모두 FAIL 로 보고했지만, 모든 후보의 성과가
기준선과 **정확히 같았고** 활성 수익이 매일 0 이었다. 원인: v1 `run.py` 가 추가 ETF 를 보조 프레임(`extra`)에만 넘겼는데
`core_lab._tranche_weights` 는 순위 후보를 `closes` 의 열에서만 고른다. 추가 자산은 한 번도 순위 후보가 되지 못했다.
따라서 **v1 의 판정은 무효**이며, 추가 자산에 대한 실제 데이터 결과는 관측된 적이 없다. v1 의 파일·결과는 그대로 둔다
(끝난 연구의 판정은 고치지 않는다).

v2 는 같은 사전 등록을 버그만 고쳐 다시 실행한다: 추가 ETF 를 순위 후보 프레임(`closes`, 가격 신호)과 총수익 프레임(Adj Close 의
`closes` 쪽)에 넣는다(`core/forward_tournament.py` 가 하는 방식과 같다). v1 결과는 '추가 자산이 없을 때와 같다'는 것만 보여 주므로
v2 의 판정 기준을 정하는 데 정보를 주지 않았다.

## 연구 질문과 범위 (v1 과 같음)

현 코어 후보군에 없는 자산군을 소수 추가했을 때, 기존 17자산 후보군과 같은 코어 규칙의 성과·위험이 나아지는가? 후보는
미국 소형주(IWM), 물가연동국채(TIP), 미국 리츠(VNQ), 신흥국 주식(VWO), 투자등급 회사채(LQD) 다섯 ETF로 고정한다.
하나씩 순위 후보에 추가한 5개와 다섯 개를 한꺼번에 추가한 묶음 1개, 모두 6개 가설. 다른 자산·규칙·비중은 바꾸지 않는다.
후보군 확장 연구이며 보유 종목 수를 늘리거나 챔피언에 편입하는 명령이 아니다.

## 입력과 기간 (v1 과 같음)

`core/core_lab.py` 의 현 `CoreConfig()` 와 현 챔피언 코어 17개(`CORE_UNIVERSE`)를 기준선으로 쓴다. 순위·필터 신호는 Close,
수익은 Adj Close(분배금 포함). 리밸런싱·체결·편도 3bp 비용은 core-rnd-v2 와 같다. 2006-01-01 부터 가져와 2008-01-01~실행일을
평가하며 기준선과 후보의 공통 날짜만 쓴다. 공통 평가 8년 미만이거나 필수 가격 열이 없으면 `NOT_EVALUABLE_DATA`.
가격을 보간·전방 채움해 상장 이전 이력을 만들지 않는다.

## 사전 판정 (v1 과 같은 관문)

core-judge/v1(`core_lab.judge`): G1 IS 초과수익 DSR ≥ 0.95(시도 6, 연 시도간 샤프 표준편차 가정 0.5), G2 마지막 2년 샤프 ≥ 기준선,
G3 IS 3등분 중 2개 이상 초과수익 양수, G4 없음(이웃 설정 없음), G5 IS 최대낙폭 악화 ≤ 5%p. 여기에 편도 8bp 비용 스트레스에서
IS 초과 CAGR > 0 을 더한다. 모두 넘으면 `PASS_REVIEW_ONLY`, 아니면 `FAIL`. 스모크는 `SMOKE_ONLY`.

G2(떼어 둔 2년, 2024-10 이후)는 v1 사전 등록을 그대로 반복하는 버그 수정 재실행이라 **그대로 유지**한다. 다만 판정 설계 규칙 3에 따라
이 구간은 이미 여러 연구가 본 구간이라 정직한 시험대가 아니라는 점을 보고서에 적는다.

## 판정 설계 규칙(2026-10-10) 추가분 — `core/research_power.py`

1. **무효 실행 가드**: 후보마다 `noop_guard(활성 수익)`. 기준선과 매일 같으면 FAIL 이 아니라 `NOT_EVALUABLE_NOOP`
   (스모크에서도 우선 적용). v1 같은 배관 버그가 다시 생기면 이 판정이 나온다.
2. **검정력 사전 계산**: `power_report(앞 구간 연수, 6)` 를 results.json `"power"` 에, `power_line` 을 REPORT.md 에 쓴다.
   앞 구간 연수는 기준선 날짜(떼어 둔 구간 이전 거래일 수 / 252)로만 정해진다. 실데이터에서 약 16.7년이면 MDE 연 IR 약 0.7.
3. **FAIL 성격**: 판정이 FAIL 이면 `classify_fail(IS 활성 연 IR, power)` 로 `fail_kind` 를 따로 적는다
   (`FAIL_UNDERPOWERED` = 관측 IR 이 양수지만 MDE 보다 작음 → 판별 불가에 가까움). **판정(verdict)은 FAIL 그대로**다.
4. **PASS 의 뜻**: `PASS_REVIEW_ONLY` 는 '전진 원장(`core/forward_tournament_v2.py`)에 올릴 후보'까지만 뜻한다.
   채택·챔피언 편입 승인이 아니며 성과를 보장하지 않는다. 엔진 반영은 사용자 확인 뒤 별도 작업이다.

## 진단 (판정에 쓰지 않음)

후보마다 평가 기간의 리밸런싱 달 중 각 추가 ETF 가 실제로 비중 > 0 으로 뽑힌 달의 비율(`selection`)과 활성 수익이 0 이 아닌 날 수
(`active_nonzero_days`)를 기록한다. 배관 수정이 실제 데이터에서 작동했다는 증거다.

## 출력

`results.json`: 기간·떼어 둔 구간 분할일·검정력·기준선 성과·후보별 성과/관문/판정/fail_kind/비용 스트레스/선택 진단,
`verdicts`(텔레그램 요약). `REPORT.md`: 사람용 요약. Codespace·대화에서는 합성 데이터 `--smoke` 만, 전체 계산은 VM 연구 실행기에서.
기간·후보·기준은 결과 확인 뒤 바꾸지 않는다. 바꾸려면 새 id 로 사전 등록한다.
