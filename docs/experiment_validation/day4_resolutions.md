## 실제 가용성으로 평가 범위를 정한다

Day 1 B3 해석의 “1996년 이후 구성종목이 있으므로 세 구간 전체가 가능”은 날짜 범위에 관한
주장이다. 구성종목의 공개시각, 당시 섹터, 발행주식수·가격의 단위, 상장폐지 처리를 인증하는
증거를 대신하지 않는다. 프로토콜 실행 가정 4번의 “point-in-time 유니버스가 존재하는 기간만”과
Day 4의 “미래 유니버스 사용 없음”, 데이터 누수 즉시 탈락 게이트를 우선 적용한다.
이는 Day 2 data_audit.md와 Day 3 인계에 이미 명시된 조건의 적용이며 Day 1 기록은 보존한다.

인증되지 않은 날짜는 S6 성과를 계산하지 않는다. 현재 섹터/현재 구성종목/최초 미래 주식수,
결측 종목 삭제·시총 0 처리·임의 현금 슬리브로 보충하지 않는다. 인증된 공통 날짜가 없으면
S1/S6 비교는 0%나 패배가 아닌 NOT_EVALUABLE이고 Day 4는 미완료다. 합성 테스트 통과나
미래 데이터를 사용한 실행이 0건인 것만으로 실제 PIT 재현 통과라고 주장하지 않는다.

## 반기 정보 시점과 검증 범위

기존 champion_strategy.py의 1월/7월 첫 세션 체결 관례와 전일까지만 가격을 읽는 선택 함수를
따라, 감사 경계는 그 직전 거래일 종가 신호 → 반기 첫 세션 시가다. 주식수·섹터·구성종목도
동일한 신호 종가까지 공개되고 유효한 기록을 요구한다. 기존 sample_universe가 체결일을
as_of_date로 받는 경로는 당일 종가를 시가 선택에 섞을 수 있으므로 그대로 호출하지 않는다.
근거: 프로토콜 실행 가정 1번, spec.execution, Day 2 latest_known/next_open_order 계약.

2007~2026-09-17 반기 경계 전부를 입력 감사한다. 원본 티커의 이탈 접미사는 보존하고
기존 정규화 결과는 캐시 검색 힌트로만 쓴다. 동일 티커가 동일 회사라는 가정은 하지 않는다.
수익률을 보고 표본이나 파라미터를 선택하지 않는다. 입력을 인증하기 전 pool/top/돈치안
숫자를 새 후보 명세로 승격하거나 새 성과 엔진을 실행할 필요는 없다.

비교 가능 기간이 생기면 Day 3 S1 저장 원장의 동일 날짜/비용률을 사용한다. 현재는 입력 감사와
비교 가능성만 확인하며 Day 5의 구간별 성과, Day 9의 부트스트랩, 최종 선택 판정은 수행하지 않는다.
