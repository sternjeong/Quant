# Day 4 PIT 입력 인계 요청

상태: **DAY_4_BLOCKED**. 이 패키지는 기존 누락표를 조회 가능한 키로 옮긴 것이며,
새 유니버스나 PIT 인증 결과가 아니다. `day4/RESUME_NOTE.md`와 `day4_resolutions.md`의
입력 계약을 그대로 적용한다. 후보·기준선·게이트·신호·파라미터 해석을 추가하지 않았다.

## 요청 범위

- `requested_boundaries.csv`: 2007-01-03~2026-07-01의 40개 반기 첫 시가와 직전 세션 종가.
- `requested_member_keys.csv.gz`: 기존 진단표의 종목/시점 20,156건을 손실 없이 보존.
- `requested_identifiers.csv`: 원본 식별자 949개, 각 최초/최종 요청 신호일과 반기 수.
- 연구 데이터 종점은 기존과 같은 2026-09-17이다. 신호 웜업과 보유기간 전체 가격도 필요하다.

`raw_identifier`는 기존 자료의 진단 키이며 안정적인 증권 ID가 아니다.
`cache_ticker_hint`는 캐시 검색 힌트뿐이다. 접미사 제거·ticker 재사용을 이유로 행을 합치지 않는다.
이 목록에 있는 종목만 가져왔다고 당시 전체 모집단을 입증한 것은 아니다. 권위 있는 원천의
전체 역사적 구성과 대조해 추가/누락/다른 증권을 설명해야 하며, 차이는 별도 빈티지에 기록한다.
40개 반기는 감사 범위다. 모두 인증될 때까지 기다려야 한다는 새 게이트가 아니며, 프로토콜
실행 가정 4번에 따라 실제 인증된 기간만 독립 평가할 수 있다.

## 필요한 자료와 의미

아래는 공급자 필드명에 독립적인 인계 표다. 각 필드의 명칭이 다르면 대응표를 함께 보존한다.

| 자료 | 필요한 값 | 인증할 내용 |
| --- | --- | --- |
| 구성 이력 | index_id, security_id, 원본 ticker, 가입/이탈 유효시각, 공개시각, 원천 빈티지 | 신호 종가 당시 알려져 있고 유효한 전체 S&P500 구성 |
| 섹터 이력 | security_id, 분류 체계/버전, 과거 섹터 코드, 유효시각, 공개시각, 수정 빈티지 | 현재 GICS/SIC 또는 다른 지수 예정 목록의 소급 사용 배제 |
| 증권 식별 이력 | 원본 식별자, security_id, 발행사 ID, 주식 종류, ticker 유효구간, 통화, 출처 | 발행사와 증권 구분; 복수 클래스·ticker 재사용·합병 연결 |
| 발행주식수 | security_id, 값, 관측일, 공시/실제 가용시각, accession/원천, 단위 배수, 증권 종류, 분할 기준 | 최초 미래 관측이나 수정 후 값 소급 사용 배제; 가격과 동일 단위의 시총 |
| 가격 | security_id, 거래 세션/시간대, 원시 OHLC, 조정 종가/조정계수, 거래량, 조회시각, 원천 해시 | 신호 계산에 신호일 종가까지 사용; 체결은 다음 거래 세션의 실제 시가 |
| 기업행사/상장폐지 | security_id, 사건 종류, 발표/효력 시각, 분할 배수, 배당, 합병 주식 교환/현금, 마지막 거래와 후속 처리, 원천 | 누락 종목 삭제·무한 가격 전방채움 없이 보유 경로 재구성 |

관측일·자료 조회일·데이터베이스 입력일·SEC 접수시각은 곧바로 실제 공개시각과 같다고
가정하지 않는다. 수정 이력과 공시 지연을 확인한다. 구성/섹터/주식수 및 순위에 사용되는
정보는 신호 종가 이하여야 한다. 다음날 시가와 이후 실제 보유 손익은 체결/평가에 사용하는
별도 정보이며 신호 계산으로 역유입하면 안 된다. 지수/ETF의 float-adjusted weight를
기존 총 시총/주식수 순위의 대체 값으로 도입하지 않는다.

모든 신규 파일은 별도 디렉터리에 URL 또는 공급자·조회 UTC·바이트 수·SHA-256을 남긴다.
기존 동결 데이터나 과거 감사 파일은 덮어쓰지 않는다. 실제 자료가 들어온 뒤 원천의 필드 의미와
증거를 검사해야 한다. 이 요청 문서와 공급자의 제품 소개는 그 검사를 대신하지 않는다.

## 확인한 공급 경로

2026-09-20에 다음 공식 문서를 열람하고 HTTP receipt를 `source_access.json`에 저장했다.
문서 원문 3개는 로컬에만 보존한다. 검색으로 발견한 상품 설명과 실제 수령 데이터는 구분한다.

1. [S&P 공식 역사적 구성 데이터 안내](https://pages.marketintelligence.spglobal.com/SP-Dow-Jones-Indices-Constituent-Removal.html):
   2020년 공지는 역사적 구성 패키지가 별도 라이선스 대상임을 설명한다. 현재 Compustat 접근이
   있다 해도 과거 S&P 구성 패키지가 포함됐다고 추정하지 않는다. 이 공지 자체는 구성 데이터가 아니다.
2. [SPICE](https://www.spice-indices.com/): 익명 요청은 `/idp/` 로그인 페이지로 이동했다.
   실제 과거 구성/섹터 파일은 수령하지 못했다. 인증 우회나 신규 구독은 수행하지 않았다.
3. [CRSP 공식 주식 데이터 설명](https://www.crsp.org/research__trashed/crsp-us-stock-databases/):
   안정적인 증권 식별자, 가격, 주식수, 기업행사와 상장폐지 정보를 설명한다. 다만 이 페이지로
   GICS 이력이나 각 값의 과거 공개시각을 인증할 수는 없다. 기존 접근 권한 또는 적법한 내보내기가
   있다면 실제 필드/기간을 대조할 경로다. 현재 페이지는 Morningstar로 문서 이전을 안내한다.
4. S&P Index Data PDF는 VM 요청에서 HTTP 403이었다. 웹 열람도 실패했다. 검색 요약을
   원문 수령이나 실제 데이터 가용성으로 기록하지 않았다.

이 경로들의 조합이 모든 누락을 해결한다고 보장하지 않는다. 제품 소개에 없는 공개시각·빈티지·
주식 종류·분할 기준은 실제 내보내기와 제공 문서로 검증해야 한다. 외부 유료 데이터만이 유일한
해결책이라는 결론도 아니다. 이번 검색 범위에서는 전체 인증 입력을 확보하지 못했다.

## 검증과 다음 실행

생성 코드는 과거 수익률/순위에 접근하지 않는다. 원본 키 손실, ticker 합침, 미래/같은 세션
요청, 중복과 빈 표본을 테스트한다. 저장 CSV는 원본 진단표·구성 이력·독립 거래소 달력에 다시
대조한다. 이 검사는 인계 파일의 정확성이며 실제 미래 유니버스 부재나 S6 체결 검증이 아니다.

전체 입력이 인증된 반기가 생기면 기존 인계 절차대로 남은 S6 세부를 성과 조회 전에 확정하고,
체크포인트→판단 기록→즉시 Telegram 보고를 수행한다. 이후 5/10/25bp 다음 시가 재현과
S1 저장 원장의 공통 날짜 비교를 수행한다. 지금은 인증 반기/공통 날짜 0개, 비교 6개 모두
NOT_EVALUABLE이다. Day 5를 시작하지 않는다.
