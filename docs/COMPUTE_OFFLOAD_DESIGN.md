# 2코어 VM 부하 줄이기 + 바깥 계산 자원 쓰기 설계 (2026-11-15)

사용자 요청: "2core 밖에 없는 나에게 너무 시스템이 과부하되지 않도록 하는 설계", "클로드 자체 컴퓨팅 자원을 내 자원처럼 잘 활용하는 설계".

상태 표기: **구현**(이 변경에 들어감) / **제안**(사용자 결정 필요, 아직 안 함).

## 1. 진단 (2026-11-15 VM 실측)

- 사양: 2코어(aarch64), 메모리 11.9GB, 스왑 없음.
- CPU 압박: `/proc/pressure/cpu` some avg10~300 이 65~75%. 실행할 일이 있는데 코어를 못 받는 시간이 그만큼이라는 뜻이다.
- 남은 메모리: 약 1.3GB. 연구 실행기가 "VM 여유 메모리 부족으로 양보"로 중단된 적이 있다.
- 연구가 굶은 정도: 내부자 연구는 회차마다 1시간을 썼는데도 분기 파일을 1개만 처리했다. 같은 작업을 혼자 돌리면 6초다. CPU 가드(80% 넘으면 SIGSTOP)가 거의 내내 멈춰 둔 것이다.

| 소비자 | 크기 | 성격 |
|---|---|---|
| 배포 전 전체 테스트(auto_deploy) | 코드 커밋마다 30~45분, 약 500MB | 반복·큰 부하. 연구 결과 커밋에도 돌았다 |
| 대기 중인 Claude CLI 세션(tmux) | 19개, 약 4.9GB | 거의 놀고 있다. 모델 계산은 Anthropic 쪽이고, VM 에는 node 클라이언트만 상주한다 |
| 다른 프로젝트 C6000 TI 파이프라인(make_dataset, 작업자 2) | CPU 거의 1코어 | 원래 01~06 KST 창인데 낮에도 돌았다 |
| 대회 앱 `vite build --watch` ×2 | 약 600MB | 계속 상주 |
| 연구 실행기 자식 | 300MB 안팎 | nice 5. 가드에 멈춰 진행이 안 된다 |
| 서비스(스케줄러·허브·Streamlit·텔레그램) | 합 약 0.8GB | 꼭 VM 에 있어야 하는 것 |

## 2. 원칙

1. **VM 은 상시 서비스 호스트다.** 꼭 VM 에 있어야 하는 것만 남긴다.
   - DB, 스케줄러 기록, Alpaca paper, 텔레그램, 관제 센터 화면
   - 가벼운 매일 수집
2. **몇 분~몇 시간 몰아서 쓰는 계산은 VM 밖으로 보낸다.**
3. **바깥 자원은 무료이고 확실한 것부터 쓴다.**

| 바깥 자원 | 무엇 | 장점 | 한계 |
|---|---|---|---|
| **GitHub Actions** | 공개 저장소는 GitHub 호스팅 실행기 사용이 무료. ARM/x86 4 vCPU·16GB, 잡당 6시간, 동시 20개 | 열린 인터넷, 비밀값(secrets) 지원. 이미 야간 스냅샷에 쓰고 있다 | 로그가 공개된다(비밀값은 가려짐). Yahoo 가 데이터센터 IP 를 자주 막는다 |
| **Claude Code 클라우드**(claude.ai/code 세션·예약 루틴) | Anthropic 이 관리하는 격리 환경에서 저장소를 클론해 코드 작성·실행·테스트·브랜치 push·PR 을 한다 | VM 메모리·CPU 를 전혀 쓰지 않는 에이전트 작업. 예약 실행 가능 | 사용자 Claude 요금제 사용량에서 빠진다. 네트워크 허용 범위·환경변수를 클라우드 환경 설정에서 정해야 한다. 몇 시간짜리 숫자 계산용은 아니다 |
| VM | 지금 그대로 | 상태·키·DB 가 여기 있다 | 2코어 |

같은 Claude 라도 계산이 어디서 일어나는지가 다르다.

- **VM 에서 띄운 Claude CLI(tmux):** 생각은 Anthropic 서버가 하지만, 그 세션이 실행하는 명령(테스트·스모크·빌드)은 VM 코어를 쓴다. 세션 하나도 node 프로세스로 200~400MB 를 차지한다.
- **클라우드 세션:** 둘 다 바깥에서 일어난다.

## 3. 1단계 — 구현

배포 관문을 바깥으로 옮겼다.

- `.github/workflows/tests.yml`
  - 커밋(main push·PR)마다 전체 테스트를 GitHub Actions 에서 돌린다. ARM 실행기 4개로 나눠 병렬로 돈다.
  - Python 3.12 를 쓰고, 패키지 버전은 `.github/constraints-vm.txt`(VM venv 의 pip freeze)로 VM 과 맞춘다.
  - 마지막 `test-gate` 잡이 4개 묶음 결과와 텔레그램 러너 unittest 를 합쳐 하나의 성공/실패를 낸다.
- `deploy/ci_status.py`: 커밋의 `test-gate` 결과를 GitHub API 로 읽어 success/failure/pending/none/error 중 하나로 출력한다. 표준 라이브러리만 쓰고 토큰은 필요 없다.
- `deploy/auto_deploy.sh`
  - **연구 결과·docs·`*.md`·야간 스냅샷만 바뀐 커밋:** 코드가 그대로이므로 테스트 없이 반영한다. 연구 실행기 결과 커밋이 하루 여러 번 오는데, 이제 이 커밋들의 VM 테스트 시간이 0이 된다.
  - **그 밖의 커밋:** CI 결과를 본다.
    - 성공이면 VM 테스트 없이 반영한다.
    - 실패면 반영하지 않고 실행 주소와 함께 알린다.
    - 대기 중이면 조용히 다음 틱을 기다린다.
  - **40분(`AUTO_DEPLOY_CI_WAIT_SECONDS`) 안에 결과가 없을 때:** 예전처럼 VM 에서 직접 테스트하되 `nice 19`·`ionice idle` 로 돌린다.
  - **되돌리기:** 설정 하나로 예전 방식으로 돌아간다(`AUTO_DEPLOY_CI_GATE=off`).
- **예상 효과:** 코드 커밋마다 VM 코어 하나를 30~45분 쓰던 것이 0이 된다. 남는 코어는 연구 실행기와 서비스가 쓴다.
- **유지 규칙:** requirements.txt 를 바꿔 VM 에 새 버전이 깔리면 VM 에서 `pip freeze` 로 `.github/constraints-vm.txt` 를 다시 만든다.

## 4. 2단계 — 제안: VM 메모리 예산

- **(a) 놀고 있는 Claude 세션 정리:** 마지막 입력 뒤 24시간 넘게 붙은 사람이 없는 tmux 의 claude 세션을 관제 센터에 목록으로 보여 주고, 버튼으로 닫는다. 자동으로 닫을지는 사용자가 정한다(진행 중인 대화가 있을 수 있음). 3~4GB 를 돌려받을 수 있다.
- **(b) systemd 슬라이스로 몫 정하기:**
  - 서비스는 그대로 둔다.
  - 연구 실행기·로컬 테스트는 `CPUWeight=20`, `MemoryHigh` 상한으로 묶는다.
  - 다른 프로젝트(사용자 세션 아래)는 사용자가 원하면 `user.slice` 에 `CPUWeight` 를 낮춘다.
  - 지금 가드(80% SIGSTOP)보다 커널이 공정하게 나눠 준다.
- **(c) 다른 프로젝트 시간 창:** TI 파이프라인을 01~06 KST 안에서만 돌게 하는 것, `vite --watch` 를 필요할 때만 켜는 것은 그 프로젝트 소유자(사용자)가 결정한다.

## 5. 3단계 — 제안: 연구 잡을 GitHub Actions 에서 돌리기

- **방식**
  - `job.json` 에 `"runner": "github"` 를 둔다.
  - VM 연구 실행기는 그 잡을 직접 돌리지 않고 `research.yml` 워크플로를 `workflow_dispatch(job_id)` 로 부른다.
- **워크플로가 하는 일**
  1. 5시간 50분 예산으로 `run.py --out --checkpoint` 를 돌린다.
  2. 체크포인트는 actions/cache(키: 잡 id)로 넘긴다.
  3. 종료 코드 3이면 자기 자신을 다시 부른다.
  4. 끝나면 `research/results/<id>/` 를 지금과 같은 형식으로 커밋한다. 이 커밋은 1단계의 '결과만 바뀐 커밋' 경로로 테스트 없이 반영된다.
- **맞는 잡과 확인할 잡**
  - SEC·Ken French·FRED·Alpaca 자료만 쓰는 잡(insider-form4, lazy-prices, profit-tilt 류)은 바로 맞는다.
  - yfinance 가격을 대량으로 받는 잡은 GitHub IP 에서의 제한을 먼저 시험한다. 막히면 VM 이 가격 캐시를 압축해 아티팩트로 넘기는 방식을 쓴다.
- **필요한 것**
  - 저장소 secrets 에 SEC User-Agent, Alpaca 데이터 키를 넣어야 한다. 사용자가 GitHub 설정에서 직접 넣고, 값은 문서에 적지 않는다.
  - 로그가 공개된다는 점을 받아들여야 한다. 연구 결과는 지금도 공개 저장소에 커밋되고 있다.

## 6. 4단계 — 제안: 에이전트 작업을 Claude 클라우드로

- **옮길 대상**
  - 프런티어 에이전트(화·목·토·일 05:00), 대회 스카우트, 코드 정리·리뷰 같은 "생각 + 짧은 실행" 작업
  - 지금은 VM tmux 의 Claude CLI 가 돌며 VM 에서 스모크·테스트를 실행한다.
- **어떻게 바뀌나**
  - Claude Code 예약 루틴(클라우드)으로 옮기면, 저장소를 클라우드에서 클론해 스모크를 돌리고 브랜치를 push 해 PR 을 연다.
  - 1단계 CI 가 테스트한다.
  - `test-gate` 통과 시 자동 병합하는 규칙을 두면 사람 손 없이 main 으로 간다.
- **결정할 것**
  - 클라우드 환경의 네트워크 허용(SEC·FRED 등)과 환경변수
  - 요금제 사용량
  - 자동 병합 허용 여부
