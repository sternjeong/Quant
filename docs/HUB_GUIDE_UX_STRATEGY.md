## (a) 현재 문제 진단 — 390x844(폰) 화면에서 실제로 본 것

스크린샷: `/workspaces/.quant-wt/shots/guide_before_*.png` (0~5 는 스크롤 위치별, `_routines`·`_jobs`·`_entry`·`_search` 는 해당 부분).

1. **한 페이지가 폰 화면 약 42장 길이(35,439px)이고 접이식 목록(details)이 123개다.** 화면 14·모듈 76·잡 29(표)·도구 19·운영 8·용어 38·루틴 6이 모두 한 문서에 이어 붙어 있다. 원하는 항목까지 가려면 긴 스크롤을 하거나 검색어를 먼저 알아야 한다.
2. **첫 화면에서 무엇을 해야 할지 모른다.** 첫 화면(`guide_before_0`)은 제목·설명 문단·배포 버전·목차 알약 9개·검색창, 그리고 '처음 보는 분을 위한 안내'의 긴 문단으로 끝난다. 이 안내는 문단 6개로 폰 화면 약 2장(`guide_before_1`)을 차지하고, 실제로 할 일(상황별 사용법)은 그 다음(y≈1,860px)에야 나온다.
3. **모든 것이 같은 무게다.** 매일 쓰는 '매일 아침 5분 점검'과 거의 볼 일이 없는 내부 엔진 모듈이 같은 카드 모양·같은 크기로 나열된다(`guide_before_3`, `guide_before_4`). 무엇이 중요한지 시각적 위계가 없다.
4. **참고서형이지 과업형이 아니다.** 루틴(과업)은 있지만 펼치면 글 목록뿐이다. 단계가 "화면 '챔피언 전략'에서…"라고 말해도 그 화면으로 가는 링크가 없고, 그 화면의 설명으로 가는 링크도 없다. 사용자는 다른 탭(퀀트 대시보드)을 열어 사이드바에서 직접 찾아야 한다.
5. **전문용어가 설명 없이 나온다.** PIT, shadow, unknown, hold-band, DSR, fingerprint 같은 용어가 본문에 그대로 나오고, 뜻은 페이지 맨 아래 용어집(y≈26,600px)에만 있다.
6. **자동 잡 표가 폰에서 깨진다.** 4열 표를 390px 에 넣어 '결과 보는 곳' 열이 좁아지면서 행 하나가 화면 절반 이상의 빈 공간을 만든다(`guide_before_jobs`).
7. **검색 결과가 보이지 않는다.** 검색어를 넣어도 첫 화면은 그대로이고(`guide_before_search`), 걸러진 항목은 아래 어딘가에서 펼쳐진다. 결과가 몇 개인지, 어디에 있는지 알려 주지 않는다.
8. **관제 센터와 모양이 다르다.** 공통 디자인(`hub/ui.py`)의 상단바·내비게이션이 없고 색·글꼴이 다른 옛 스타일이라, 설명서에 들어오면 다른 사이트처럼 보이고 돌아가는 길은 맨 위 "← 관제 센터로" 링크 하나다.
9. **지금 상태와 끊겨 있다.** 관제 센터 첫 화면은 "모든 시스템 정상/확인이 필요합니다" 판정을 보여 주지만, 설명서는 지금 문제가 있는지 모른 채 일반론만 보여 준다. 알림이 와서 설명서를 연 사용자는 어느 잡이 문제인지 다시 찾아야 한다.

## (c) UX 원칙

1. **과업 중심 진입** — 첫 화면은 "무엇을 하려고 하나요?"로 시작한다. 목차가 아니라 할 일을 고르게 한다.
2. **점진적 공개** — 목록에는 이름 + 한 줄 요약 + 상태 알약만. 세부는 누른 뒤 별도 페이지에서. 한 페이지에 모든 것을 펼치지 않는다.
3. **쉬운 말 우선, 용어는 처음 나올 때 풀어 준다** — 핵심 항목에는 '처음 보는 사람용 한 줄'(plain_summary)을 먼저 보여 주고, 본문 속 용어집 용어는 처음 나올 때 누르면 뜻이 바로 뜨게 한다(페이지를 떠나지 않음, 용어집 앵커로도 이동 가능).
4. **스캔 가능한 구조** — 관제 센터와 같은 행 목록(`ui.row_list`)·판정 배너(`ui.verdict`)·알약(`ui.pill`)을 쓴다. 색은 상태를 뜻할 때만.
5. **지금 상태와 연결** — 설명서 첫 화면에 관제 센터와 **같은 판정 함수**의 결과를 보여 주고, 문제가 있는 잡은 그 잡의 설명(알림이 오면 할 일)으로 바로 연결한다.
6. **검색 개선** — 모든 하위 페이지 항목을 대상으로, 입력하는 즉시 결과를 목록으로 바로 아래에 보여 준다(결과 개수 표시). JS 가 없어도 `/guide/search?q=` 로 동작.
7. **빠른 이동** — 과업 단계마다 해당 화면 열기(퀀트 대시보드로 바로)·설명 보기 버튼. 모든 하위 페이지에 경로(개요 › 설명서 › …)와 상단 내비게이션.
8. **모바일 우선** — 390px 에서 가로 스크롤 없음, 누르는 영역 44px 이상, 표 대신 행 목록.

## (d) 새 정보 구조(IA)

```
/guide                      첫 화면(허브): 지금 상태 · 검색 · 할 일 카드 · 처음이라면 · 전체 목록 바로가기 · 배포 버전
/guide/start                처음 보는 분을 위한 안내(START_HERE 문단)
/guide/tasks/<루틴 id>       과업 페이지: 언제·한 줄 요약 → 단계 카드(번호, 본문, 화면 열기 ↗, 설명 보기) → 팁·주의 → 이 과업에서 쓰는 화면
/guide/screens              화면 목록(업무공간별, 코드에서 자동) → /guide/screens/<Streamlit 경로>
/guide/jobs                 자동 잡 목록(분류별, 시각·켜짐/꺼짐 자동) → /guide/jobs/<job_id>
/guide/modules              엔진 모듈 목록(그룹별, 상태 알약) → /guide/modules/<모듈 이름>
/guide/tools                운영 도구 목록(위험도 알약) → /guide/tools/<스크립트 이름>
/guide/ops                  운영·알림 목록 → /guide/ops/<id>
/guide/glossary             용어집(항목마다 #t-… 앵커)
/guide/changes              최근 변경(git 자동) + 배포 버전
/guide/search?q=            검색 결과(서버 렌더, JS 없을 때)
/guide/search.json          검색 인덱스(클라이언트가 한 번 받아 필터)
```

항목 상세 페이지 순서: 제목·요약 → (화면이면 '화면 열기' 버튼) → 낡음 경고 → 한눈에(쉬운 한 줄·예시) → 언제 쓰나 → 사용 순서 → 결과 읽는 법 → 주의 → 관련 자동 잡·모듈·과업 링크 → 확인일·근거.

화면 링크 주소: 퀀트 대시보드 주소는 `hub/apps_registry.py` 의 `streamlit` 슬롯 `url` 에서 읽고, 화면 경로는 Streamlit 이 파일 이름에서 만드는 규칙(앞 숫자·밑줄 제거, 기본 화면은 빈 경로)과 같게 만든다. 테스트가 Streamlit 자체 함수와 결과를 대조한다.

## (e) 바꾸는 것 / 유지하는 것

바꾸는 것
- `hub/guide/render.py`: 한 페이지 렌더러 → 경로별 렌더러(`render_route`)와 공통 디자인(`hub/ui.page`) 사용. 옛 전용 CSS 삭제, 설명서 전용 CSS 는 최소(단계 카드·할 일 타일·용어 팝업)로 `ui.py` 색 변수 사용.
- `hub/server.py`: `/guide/*` 라우트 추가(검색 인덱스는 JSON). 판정은 `_overview` 를 그대로 재사용하는 `current_overview()` 를 추가해서 설명서가 부른다(`render_dashboard` 는 건드리지 않음).
- `hub/guide/schema.py`: 선택 필드 추가 — `PageGuide.plain_summary`, `PageGuide.example`, `Routine.plain_summary`, `Routine.card_title`, `Routine.icon`. 핵심 항목(루틴 6개, 자주 쓰는 화면 6개)에 채움. 사실 내용은 기존 설명·코드에서 확인되는 것만.

유지하는 것
- coverage 게이트(`hub/guide/check.py`, `tests/test_hub_guide.py`)와 형식 검사 — 규칙 그대로.
- 자동 생성 부분: 화면 목록(`core.app_navigation`), 잡 시각·켜짐/꺼짐(`job_schedule`·`process_registry`), 최근 변경·배포 버전(git).
- 확인일 표시와 낡음 경고("근거 코드가 수정됐습니다") — 상세 페이지에 그대로, 목록에는 '낡았을 수 있음' 알약.
- 모든 텍스트 escape.
- `content_*.py` 의 기존 사실 문장.

## (f) 성공 기준

- 첫 화면(폰 1장 안)에서 지금 상태 판정과 "무엇을 하려고 하나요?" 할 일 카드가 보인다 → 3초 안에 '지금 할 일'을 안다.
- 어떤 항목이든 첫 화면에서 **탭 2~3번**(목록 → 상세, 또는 할 일 → 단계의 화면 열기)으로 닿는다.
- 검색어를 입력하면 입력창 바로 아래에 결과 개수와 결과 행이 뜬다(모든 하위 페이지 항목 대상).
- 390px 에서 가로 스크롤 0, 페이지 오류(pageerror) 0, 누르는 행·버튼 높이 44px 이상.
- 한 페이지 최대 길이: 가장 긴 목록(엔진 모듈 76개)도 한 줄 행이라 기존 35,000px 대비 크게 짧다.
- 기존 게이트 테스트 전부 통과 + 새 라우트·404·링크·검색 인덱스·escape·viewport 테스트 통과.
